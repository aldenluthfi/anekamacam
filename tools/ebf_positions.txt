# EBF suite cases, read by tools/ebf-suite.sh.

# Format, one case per line:
#   variant | label | position command | depth
#
# The position command is sent verbatim, so it must be one both engines
# accept. `position startpos moves ...` is that command: the move notation is
# identical in fairy-stockfish for every variant here (verified by replaying
# each list into it and comparing the board), while the FENs are not -- our
# crazyhouse pocket and shogi spellings are our own dialect's.
#
# The label records where the position came from. `aneka-pN` is ply N of a
# self-play game by this engine, `fsf-pN` ply N of a fairy-stockfish self-play
# game, and both sources appear in equal numbers for every variant: positions
# sampled only from our own games select for the positions our own play
# reaches, which is a different claim than the one these cases are used for.
# Each game opens on four random plies so the sources are not one game each.
#
# crazyhouse carries `startpos` as well as its midgame cases, and standard
# does the same. The startpos-versus-midgame pair is what separates a deficit
# that belongs to the hand from one that belongs to the board, and standard is
# the control the drop-variant ratio is stated against, so it is eight cases
# rather than the two an earlier throwaway version used.
#
# Depth is per variant, chosen so one pass is minutes rather than hours;
# the suite reports the whole node curve, so a gate written against a
# shallower depth reads the same run.
